# Agent Factory — سنگ‌بنا v2 (مانیفست + پایپ‌لاین + نقشه‌ی راه)

تاریخ: ۱۳ اکتبر ۲۰۲۶ · جایگزین Business Plan v1.0 · وضعیت: پیش‌نویس برای تأیید مهدی

## ۰. چه چیزی از v1 تغییر کرد (و چرا)

1. «فهمیدن عمیق مهارت» کوچک شد. دلیل (از استدلال مهدی): ساخت دوباره‌ی یک مهارت با Claude Code / Codex / Kimi ارزان است. گلوگاه واقعی «ساخت» نیست؛ گلوگاه «تقاضا + دریافت پول» است.
2. «راستی‌آزمایی ادعا» با «آزمون فروش» جایگزین شد. ما لازم نیست بدانیم ایجنت دیگر واقعاً پول گرفته یا نه. لازم است بدانیم کسی به ما پول می‌دهد یا نه. آزمون فروش ارزان‌ترین الک جهان است.
3. حجم ورودی بالا رفت (ایده‌ی مهدی)، اما با الک ارزان چندمرحله‌ای. حجم بدون الک فقط خاک بیشتر است، نه طلای بیشتر.
4. لایه‌ی پرداخت از مغز پروژه جدا شد و یک «دروازه‌ی صفر» گرفت. تا آن دروازه باز نشده، پروژه در «حالت بدون پول» کار می‌کند و متوقف نمی‌شود.
5. زمان‌بندی وارونه شد: ابتدا تقاضا و دریافت، بعد اتوماسیون.

## ۱. مانیفست v2

Agent Factory دنبال بهترین مدل نیست. دنبال مهارتی است که (الف) کسی برایش پول می‌دهد، (ب) ما با هوش مصنوعی ارزان بازسازی می‌کنیم، (ج) می‌شود تکرارش کرد.
اصل‌ها:

* هر ادعا «بو» است، نه «مدرک». بو ما را به سمت آزمایش می‌برد، نه به سمت باور.
* مدرک نهایی فقط یکی است: پول واقعی و قابل اثبات روی زنجیره.
* بازسازی یعنی ساخت پیاده‌سازی خودمان از روی رفتار عمومی و قابل مشاهده. جاسوسی، دسترسی به داده‌ی خصوصی و نقض شرایط سرویس خارج از مرز است.
* یک قدم در هر زمان. فقط یک اسپرینت فعال داریم.
* هر مشکل راه‌حل دارد، اما راه‌حل باید قانونی و صادقانه باشد.

## ۲. گزارش «بو» (جایگزین استخراج سنگین)

برای هر ایجنت یا منبع، فقط چهار پاسخ ثبت می‌شود:

1. چه کاری می‌کند؟
2. کدام مشکل را حل می‌کند و چه کسی آن مشکل را دارد؟
3. تبلیغش چه می‌گوید و قیمت یا مدلش چیست؟
4. آیا می‌شود (الف) با او وارد گفت‌وگو شد، (ب) رفتار عمومی‌اش را زیر نظر گرفت؟
سپس «امتیاز بو» با الک‌های ارزان زیر محاسبه می‌شود.

## ۳. الک چندمرحله‌ای (برای حجم بالا)

به ترتیب هزینه، از ارزان به گران:

* F1: قیمت یا پیشنهاد مشخص دارد؟ (قانون متنی، بدون مدل زبانی)
* F2: نشانی عمومی کیف پول، شناسه‌ی تراکنش، یا طرف مقابل عمومی دارد؟
* F3: تقاضا مستقل از او وجود دارد؟ (آگهی کار، جایزه، درخواست انسان‌ها)
* F4: هوش مصنوعی در کمتر از یک روز بازسازی می‌کند؟
* F5: قانونی و مجاز است؟
فقط مواردی که از F1 تا F3 رد شوند به مدل زبانی گران می‌رسند. سقف هزینه برای هر ۱۰۰۰ پست تعیین می‌شود.
معیار توقف: بعد از ۵۰۰۰ مورد اگر هیچ کاندیدایی از دروازه‌ی G1 رد نشد، منبع عوض می‌شود، نه کد.

## ۴. منابع (Agent 06 چندمنبعی)

مولت‌بوک، Moltweet، Neblis، AgentDiscuss، Reiki by Web3Go.

* وضعیت بررسی من: Moltweet، AgentDiscuss و Reiki در فهرست‌های محصول دیده شدند (پلتفرم‌های کوچک). Neblis را نتوانستم با اطمینان پیدا کنم؛ شاید املا فرق دارد (Nebils؟). باید مهدی لینک بدهد.
* منابع تقاضا (مهم‌تر از منابع ادعا): تابلوهای کار، جایزه‌ها (bounty)، بازارهای ایجنت، درخواست‌های انسانی.
* هر منبع یک «آداپتور» جدا دارد. قبل از ساخت آداپتور، شرایط استفاده و API آن منبع خوانده می‌شود.
* متن خام همه‌ی منابع «داده‌ی ناامن» است. ایجنتِ خواننده ابزار و کلید ندارد (دفاع در برابر تزریق دستور).

## ۵. پایپ‌لاین v2 و دروازه‌ها

```
S1 SNIFF      Agent 06: جمع‌آوری چندمنبعی + الک F1-F3          → G1 (امتیاز بو ≥ آستانه)
S2 CARD       کارت کاندیدا: ۴ پاسخ + شواهد تقاضا                  → G2 (تأیید انسان، ۵ دقیقه)
S3 REPLICATE  ساخت مهارت توسط Claude Code/Codex/Kimi + مشخصات    → ساخته شد + تست خودکار
S4 TEST LAB   مجموعه‌ی تست طلایی، کیفیت، هزینه‌ی هر کار           → G3 (کیفیت ≥ آستانه، هزینه < قیمت)
S5 OFFER      آزمون فروش: آگهی/پیشنهاد/جایزه                      → G4 (اولین پاسخ یا قیمت‌دهی واقعی)
S6 DELIVER    تحویل + دریافت پرداخت + تأیید فقط‌خواندنی روی زنجیره → G5 (پول واقعی تأییدشده)
S7 IMPROVE    ثبت هزینه/درآمد، بهبود، تکرار
```

دروازه‌ی صفر (G0): «مسیر پرداخت قانونی». تا بسته است، S1 تا S5 در «حالت بدون پول» اجرا می‌شوند. فقط S6 منتظر می‌ماند.
دروازه‌ی شکست: هر دروازه سه شاخه دارد: عبور، تلاش دوباره (حداکثر ۲ بار)، کنار گذاشتن کاندیدا.

## ۶. لایه‌ی پرداخت v2

* واحد: تتر یا استیبل‌کوین دلاری. شبکه و توکن در سند جدا و پیش از S6 مشخص می‌شود.
* ایجنت کلید خصوصی ندارد. کیف پول فقط آدرس عمومی دارد. سیستم فقط می‌خواند و ثبت می‌کند.
* تأیید پرداخت (فقط‌خواندنی): شناسه‌ی تراکنش ← دو منبع مستقل ← نشانی قرارداد توکن با نشانی رسمی ← گیرنده = آدرس ما ← مبلغ = قیمت ← تأییدیه‌ی کافی ← ثبت زنجیره/هش/بلوک/مبلغ/زمان.
* G0 (قانونی بودن): مالک کیف پول و محل واقعی آن صادقانه تعریف می‌شود. مشورت با وکیل تحریم/رمزارز قبل از اولین پیشنهاد پولی. سیستم هیچ مکانیزمی برای پنهان‌کردن مبدأ یا مالک پول نمی‌سازد.
* ساختار هزینه: کیف پول «درگاه ورودی» است، اما هزینه‌ی کارگرها (اشتراک‌ها و توکن) باید با یک مسیر قانونی تأمین شود. این مسیر در G0 تعیین می‌شود.

## ۷. نقش کارگرها

* Claude Code: معمار و ساختن S3/S4، بازبینی کد.
* Codex و Kimi: کارگر موازی برای آداپتورها و تست‌ها.
* Claude (این چت): مرکز فرماندهی، تصمیم، بازبینی «کنسول».
* قانون: هر کارگر یک وظیفه‌ی کوچک با تعریف «انجام شد» دارد.

## ۱۰. تصمیم‌های باز برای مهدی

1. آدرس دقیق Neblis؟ (و لینک‌های دیگر منابع)
2. اولین کاندیدای مهارت: از بو بیاید یا از تخصص خودت (طراحی/برند) به‌عنوان شاهد اول؟
3. سقف هزینه‌ی هفتگی و تاریخ توقف.
4. چه کسی G2 (تأیید ۵ دقیقه‌ای) را می‌دهد: خودت یا بعداً خودکار؟
5. ارسال کد Agent 06 برای شروع اسپرینت ۰.
